# Parts library

One JSON file per part (`<id>.json`), plus an optional STEP model (`<id>.step`) next to it. The MCP server reads these files; Claude never invents dimensions, so every number the design uses has to come from here.

## Conventions

- All lengths are in **millimetres**, angles in degrees.
- **Origin**: the bottom-left corner of the part's footprint, on its bottom face. For a PCB that is the corner of the board on the solder side.
- **Axes**: +X along the part's length, +Y along its width, +Z up (away from the bottom face).
- A position is `[x, y, z]` in the part's own frame. The MCP server applies the placement transform.
- `verified` is `false` until someone has checked the number against the real part with calipers. Set `verified_by` and `verified_on` when you do.
- Common mechanism parts (NEMA 17 stepper, A4988/DRV8825 drivers, 2020 extrusion, 608 and LM8UU bearings, GT2 pulleys, T8 lead screw, TT rover motor and wheel, limit switch, M3/M5 screws) are generated by `mcp-server/examples/mechanism_parts.py`; edit that script and rerun it rather than the files.
- The double inverted pendulum's parts (and their `.step` shapes, e.g. the toothed rack and pinion) are generated by `mcp-server/examples/pendulum_parts.py`; edit that script and rerun it rather than the files.

## Fields

| Field | Meaning |
|---|---|
| `id` | File name without `.json`, kebab-case. |
| `name`, `category` | Human-readable name; one of `board`, `input`, `output`, `fastener`, `misc`. |
| `source` | Where the dimensions came from (datasheet, drawing, STEP file, calipers). |
| `step_file` | STEP model next to this file, or `null` if we don't have one yet. |
| `body` | Bounding box of the part itself: `size` `[x, y, z]`. For a PCB, `z` is the board thickness. |
| `envelope` | Bounding box including everything mounted on it (`min`, `max`), used for a first-pass fit check. |
| `mounting_holes` | `{id, position, diameter}`. Position is the hole centre on the bottom face. |
| `connectors` | Things the enclosure has to leave reachable: `{id, type, face, center, size, protrusion}`. `face` is the side it is reached from (`-x`, `+x`, `-y`, `+y`, `+z`), `center` is the middle of the opening on that face, `size` is `[width, height]` of the opening, `protrusion` is how far it sticks out past the body. Optional `clearance` overrides the enclosure's 0.5 mm per side, e.g. a tighter LED hole so the flange can't pass through. |
| `pins` | Electrical connection points for wiring: `{id, label, position, direction}`. `position` is where a wire attaches (top of a header socket, end of a leg), `direction` the way the wire leaves it (default `[0, 0, 1]`). |
| `electrical` | Optional power data for the checks in `bench/power.py`. Boards: `logic_v`, `pin_ma` (safe current per GPIO pin), `pin_abs_ma`, `total_pin_ma`, `rails_ma` (what the `5v` / `3v3` pins can supply), `five_v_tolerant`. Parts: `supply_v` `[min, max]`, `current_ma` (typical), `peak_ma` (stall, full brightness), `needs_driver` (too much for a GPIO pin), `signal_v` (`"supply"` when its outputs swing to its supply, or a number), `pin_max_v` (`{pin id: volts}` for inputs that take less than the board's logic level), `note`. LEDs: `vf` by colour, `max_ma`. |
| `lid_mount` | Parts that mount under the lid and poke through it (buttons, LEDs): `{ "z": ... }`, the height in the part frame where the lid's underside sits, e.g. the top of a tactile switch's square housing or an LED's flange. The enclosure puts its lid there, and only the part's `+z` connectors continue through the lid. Leave it out for parts that live inside the case. |
| `keep_out` | Boxes (`min`, `max`) nothing else may occupy, e.g. tall components or header pins. |
| `notes` | Anything an assembler or the design tools should know. |
| `appearance` | Optional, for the 3D guide only (never used for fit checks): `material` (a name from `materials/materials.json`: a seamless texture, tinted by the colour, tiled at its real size; made by `mcp-server/examples/make_materials.py`), `color` (`#rrggbb`), `metallic` and `roughness` (0..1), `source` (where the look came from) and `top`, a picture on the body's top face: `{"image": "<file next to this JSON>"}` for a photo, or `{"pcb": {"mask", "silk"?, "title"?, "chips": [{at, size, label}]}}` to draw a PCB with a pad on every pin and a hole on every mounting hole (`mcp-server/physical_studio/textures.py`). |
| `verified`, `verified_by`, `verified_on` | Caliper check status. |
